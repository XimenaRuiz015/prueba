ENTREGABLE 1 • DECISIÓN ARQUITECTÓNICA FUNDAMENTADA

Single-Page Application (SPA Reactiva MVVM) + Entrega Híbrida RESTful

Para Equigrup S.A.S. implementamos una arquitectura Single-Page Application (SPA) desacoplada bajo el patrón Model-View-ViewModel (MVVM) conectada a un API Gateway ASGI en FastAPI y 2 Microservicios independientes. Todas las vistas operativas conviven en memoria del cliente, eliminando las recargas completas de página durante las operaciones de campo en refinerías y plantas industriales.

< 2 ms Conmutación de Vistas y Filtros en Memoria
100% Persistencia del Estado del Chatbot RAG
~42 MB Huella de Memoria RAM en Render Cloud
248 Registros Auditados (196 Docs + 52 SQL)
🤖

1. Persistencia del Chatbot IA (RAG)

Mientras un ingeniero consulta el tiempo de curado de Chockfast Red o tolerancias de la norma API RP 686 en el chat, puede cambiar a la pestaña del catálogo para revisar el informe EG24-184S de Cenit Planta Galán o calcular kits en el Microservicio 1 sin que la conversación ni las fuentes citadas (fuentes_consultadas) se borren del DOM.

⚡

2. Consumo Óptimo de Endpoints REST

El backend FastAPI solo transfiere payloads JSON ultraligeros (GET /api/proyectos, POST /chat). El filtrado facetado por carpeta_modulo, cliente_entidad (Ecopetrol, ArcelorMittal, Reficar) y estado_operativo ocurre localmente en ProjectsViewModel sin recargas HTTP redundantes.

🌐

3. UX Fluida y Autogestión CMS

El módulo de Banner Hero Autogestionable (GET /api/blog?solo_banner=true) hidrata dinámicamente la portada con videos e imágenes de obras reales, mientras que los manuales normativos (API 686.pdf, PAC-EG-073) se sirven en streaming binario inline (GET /api/documentos/*).

ESPECIFICACIÓN FORMAL DE REQUISITOS

Fichas Técnicas Detalladas de los 5 Casos de Uso Críticos

CASO DE USOCU-01: Consultar Asistente IA mediante RAG y SQL Tool
ACTORESIngeniero de Operaciones + Motor IA RAG
RELACIONES UML<<include>> RAG, SQL, MS-2 | <<extend>> Abrir PDF
FLUJO NORMAL PASO A PASO:

1. El Ingeniero escribe su consulta técnica en #vistaChat (ej. curado de Chockfast Red bajo API 686 u obras en Cenit Planta Galán).

2. ChatViewModel envía POST /chat hacia el orquestador procesar_mensaje_equi().

3. <<include>>: El motor busca los fragmentos más relevantes en equigrup_rag.db (109 chunks de manuales PDF/DOCX) y consulta simultáneamente los 52 proyectos en equigrup_proyectos.db.

4. El LLM sintetiza la respuesta técnica adjuntando fuentes_consultadas y registra la traza en el Microservicio 2 (`ms_auditoria.db`).

Flujo Alternativo (<<extend>>): El ingeniero hace clic en "Abrir Documento ↗" y visualiza el manual API 686.pdf o el informe EG24-184S en línea.

CASO DE USOCU-02: Filtrar y Visualizar Informes Técnicos y APU
ACTOR PRIMARIOIngeniero de Operaciones / Consultor
ENDPOINT RESTGET /api/proyectos & /api/documentos/*
FLUJO NORMAL PASO A PASO:

1. El Ingeniero abre el explorador y filtra por carpeta_modulo (0.1. INFORMES TECNICOS, 0.2. COTIZACIONES, 0.3. PROCEDIMIENTOS), cliente_entidad (Ecopetrol, Cenit, Veolia, ArcelorMittal) o estado_operativo.

2. ProjectsViewModel.applyFilters() actualiza la grilla en memoria en menos de 2 ms.

3. El Ingeniero abre el documento original (EG23-133S, EG24-184S, PAC-EG-073) o lanza una consulta contextual hacia el Chatbot IA con un clic.

CASO DE USOCU-03: Autogestionar Contenido Web y Banner Hero (CMS)
ACTOR PRIMARIOAdministrador del Sistema (Freddy)
ENDPOINT RESTPOST /api/blog/publicar & toggle-banner
FLUJO NORMAL PASO A PASO:

1. El Administrador redacta una nueva publicación técnica en #vistaBlog, adjunta fotografía o video .mp4 de la obra y activa es_banner = True.

2. El backend guarda el archivo multimedia en /data/uploads/ y actualiza la tabla publicaciones_blog en SQLite.

3. El Banner Hero principal del portal público se actualiza instantáneamente sin modificar código fuente.

CASO DE USOCU-04: Indexar y Auditar Documentos en el Motor RAG
ACTORESAdministrador + Motor IA / Servicio RAG
ARTEFACTO DATOSdata/equigrup_rag.db (109 Chunks)
FLUJO NORMAL PASO A PASO:

1. El Administrador sube un nuevo informe técnico (.pdf o .docx) o procedimiento PAC-EG.

2. El módulo de ingesta extrae el texto con pypdf / python-docx, lo divide en fragmentos de 1000 caracteres y actualiza equigrup_rag.db.

3. El auditor actualiza el estado "indexado_rag": "Sí" en el dataset consolidado.

CASO DE USOCU-05: Administrar Proyectos en SQLite (TABLA_PROYECTOS_SQL)
ACTOR PRIMARIOAdministrador del Sistema
INDEXACIÓNSí (Vía SQL Tool en Tiempo Real)
FLUJO NORMAL PASO A PASO:

1. El Administrador registra o edita un proyecto industrial (cliente, planta, maquinaria, estado) desde el formulario CRUD o mediante un comando en lenguaje natural en el chat de Equi.

2. SQLAlchemy persiste el cambio en equigrup_proyectos.db y queda inmediatamente consultable por el Chatbot IA vía SQL Tool.
